# 给豆包的自检 Prompt

## 用之前（用户做，2 分钟）

1. 豆包工作客户端 → 左侧 **插件·技能·伙伴 → 插件 → + 添加 → 新建自定义连接器**
   - 服务器名称：`IELTS 口语教练`
   - 传输类型：**STDIO**
   - 运行命令（源码版）：`E:\雅思口语插件开发\.venv\Scripts\ielts-mcp.exe`
   - 运行命令（便携版）：`<安装目录>\ielts-mcp.bat`
   - 环境变量：`PYTHONUTF8` = `1`
2. **技能 → + 添加 → 上传技能**，选 `skills/ielts-speaking-coach/` 文件夹
3. 回到对话，把下面这段发给豆包

---

## 复制给豆包

> 我刚给你接了一个本地 MCP 插件，名字叫 **ielts-coach**（雅思口语教练），它跑在我自己电脑上。
> 请你做一次**连通性自检**，然后把结果用中文汇报给我。要求：只用真实调用结果，不要猜、不要编。
>
> 按这个顺序做：
>
> 1. **列出你现在能用的 MCP 工具**，找出属于 ielts-coach 的那些（可能带命名空间前缀）。把它们的中文用途各写一句。
> 2. 调用 **`daemon_status`**。告诉我：返回的 `ok`、`version`、`device`、以及四个模型（asr / tts / vad / pronounce）是否就绪、TTS 用的哪个引擎。
> 3. 调用 **`get_learner_context`**。只告诉我：历史课程数、最常犯的语法问题、最弱的音素。没有历史就说"空白，第一节课"。
> 4. 调用 **`start_lesson`**，参数 `part_mode="part1"`。从返回里报出：会话 id、本次话题（中文）、题目数量、**第一题的英文原文**。不要自己编题。
> 5. 如果第 4 步返回里 `window.launched` 是 false，再调用一次 **`open_window`**（参数用第 4 步的 `session_id`）。
> 6. 最后给我一段结论：
>    - 哪几步成功、哪一步失败；
>    - 如果失败，最可能的原因是什么（插件没添加 / 命令路径写错 / Python 环境缺依赖 / 8765 端口被占 / 豆包把插件跑在云端拿不到本地路径）；
>    - 我应该点哪里、改哪一项。
>
> 约束：
> - 不要调用 `start_lesson` 以外的写操作；**不要**结束课程、不要写记忆、不要生成报告。
> - 不要反复重试同一个失败调用，失败一次就停下来诊断。
> - 汇报控制在 15 行以内，分点，中文。

## 怎么判断结果

| 豆包说 | 含义 | 下一步 |
| :--- | :--- | :--- |
| 工具列表里**没有** ielts-coach 相关工具 | 插件没连上 | 回到插件页确认"已连接"；命令路径必须绝对路径且文件存在 |
| 有工具，但 `daemon_status` 报错 | 插件进程起来了、本地服务没起来 | 双击 `启动口语教练.bat`，或等 20 秒让它拉模型 |
| `start_lesson` 成功但窗口没弹 | 桌面窗口被拦/没装 pywebview | 让它调 `open_window`；仍失败就看 `%USERPROFILE%\.ielts-coach\logs\desktop-daemon.log` |
| 全部失败且报"找不到路径" | 豆包把插件跑在云端沙箱 | 改用 HTTP 连接器：`http://127.0.0.1:8765/mcp`（需要 v1.2.0） |

## 注意

- 豆包的模型是**云端**的，token 花豆包额度，不花你 dsh 的钱；音频仍只在本机。
- `start_lesson` 会打开桌面窗口，这是正常现象，不是报错。
- 如果豆包提示工具名带前缀（例如 `ielts-coach__daemon_status`），让它按实际名字调用即可。
