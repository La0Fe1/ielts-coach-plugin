# IELTS 口语教练 v2.2.2

**自动提交再升级：不再只看“句号完了没”，而是判断整段回答有没有说完。**

## 修复 / 改进（DeepSeek 纯语音模式）

v2.2.1 只把停顿放宽到约 3.5 秒，但如果你第一句说得很完整、只是停下来想第二句，仍然会被提前提交。
v2.2.2 改成**整段回答完成度判断**：

- **停顿后先分析整段内容**，而不是只看最后一个标点：
  - 结尾停在 `well / and / but / because / so / you know / kind of / 嗯 / 然后 / 所以…`
    这类**没说完的填充词、连接词、口头语** → 继续等；
  - 结尾停在 `a / an / the / of / to / in / my / that…` 这类**介词、冠词、所有格** → 继续等；
  - 只有**一句短句**（例如 `I play basketball on weekends.`）→ 也继续等，因为雅思回答通常还要补一句；
  - 至少**两句话**或**足够长（≥14 词）**且收尾干净 → 认为说完了，短暂缓冲后提交。
- **5 秒硬上限**：如果一直等不到“说完”的判断（你在想词、卡住了），最长约 5 秒就停下来提交，
  让考官接话。等待期间你一开口，计时立刻重置、不会提交。
- **「接话速度」三档**对应硬上限：`快速（最长约 3.5 秒）` / `标准（最长约 5 秒，默认）` /
  `耐心（最长约 6.5 秒）`。说完整的两句话通常在约 3.5–3.7 秒内提交。
- 手动模式与 Part 2 独白完全不变：必须点「我说完了 / 我讲完了」。

这套判断由纯函数 `assessUtterance` 实现（`shared/src/ielts.ts`），浏览器与服务端测试共用同一套规则。

## 升级步骤

1. `git pull` 拉取 v2.2.2；
2. `npm run build`（前端改动，重建 `web/dist`；无需改 `.env`、无需新增依赖）；
3. **硬刷新浏览器**（macOS `Cmd+Shift+R` / Windows `Ctrl+F5`）；
4. 设置 → 服务商「DeepSeek 纯语音」→ 按需要选「接话速度」，保存后开新一节课生效。

## 验收

- `npm run typecheck` / `npm run build` / `npm test` 全绿；新增 `server/tests/endpointing.test.ts`
  8 项，覆盖两句话说完整、单句不提交、填充词/连接词/介词尾巴、中文尾巴、逗号/省略号、空输入。
- 提交前有 `assessUtterance` 的单元测试兜底；真实浏览器里的体感仍需你戴耳机试一轮确认。

## 已知边界

- 纯语音模式的延迟 = 识别停顿判断（最多约 5 秒硬上限）+ DeepSeek 往返 + 首句 TTS；
  想要更快可切「快速」档或手动模式。
- 判断是启发式（填充词 / 连接词 / 句子数 / 词数），不是语义模型；极端口语仍可能误判。
- Firefox 不支持 `SpeechRecognition`；Chrome 识别在国内可能报 `network`，可换 Safari 或打字作答。
