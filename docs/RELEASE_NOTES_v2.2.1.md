# IELTS 口语教练 v2.2.1

**补丁版：修掉 DeepSeek 纯语音「思考停顿被打断」的真实体验问题。**

## 修复

- **考官不再在你思考时抢话**（DeepSeek 纯语音模式）：
  - 之前「自动提交」只要停顿约 1.35–1.75 秒就提交，稍微想一下词就被当成回答结束，
    考官立刻接话（实测数据：用户一句半截话提交后 628 ms 考官就开始回复）。
  - 现在停顿达到阈值后会先进入约 1 秒的**「继续说话」缓冲窗口**：这段时间里你一开口，
    这一轮就自动取消提交、继续记录，不会被截断。
  - 默认「标准」档 = 约 2.5–2.9 秒停顿 + 约 0.95 秒缓冲 ≈ **3.4–3.8 秒**才真正提交。
  - 设置里新增 **「接话速度」** 三档：`快速（约 2 秒）` / `标准（约 3 秒，推荐）` /
    `耐心（约 4 秒）` —— 思考多的同学选耐心，练抢答选快速。
  - 手动模式与 Part 2 独白不受影响：仍然必须点「我说完了 / 我讲完了」才提交。
- 提交后的考官回复、TTS 朗读、字幕与精批逻辑不变。

## 升级步骤

1. `git pull` 拉取 v2.2.1；
2. `npm run build`（本次是前端改动，重建 `web/dist` 即可，无需改 `.env`、无需新增依赖）；
3. **硬刷新浏览器**（macOS `Cmd+Shift+R` / Windows `Ctrl+F5`）；
4. 设置 → 服务商仍是「DeepSeek 纯语音」→ 按自己的习惯选「接话速度」，保存后开新一节课生效。
   已有的 Key、口令、口音等设置原样保留。

## 验收

- `npm run typecheck`、`npm run build`、`npm test` 全绿（测试项数见 `docs/V2_DELIVERY.md`）。
- 本补丁行为由真实使用数据驱动：用 `~/.ielts-coach/store.json` 里你那一节课的时间线定位到
  「用户最终字幕 → 考官回复」仅间隔 628 ms，确认是自动提交阈值过短，而不是识别或网络问题。
- **未实测**：真实浏览器里 3.4–3.8 秒的实际体感（需要你戴耳机再跑一轮确认）；真机 Safari /
  Android 的停顿感知差异。

## 已知边界

- 纯语音模式本身仍是「浏览器识别 + 文本模型 + TTS」，提交阈值越长，考官开口越晚；
  想要「说完立刻接话」可切回「快速」档。
- Firefox 不支持 `SpeechRecognition`；Chrome 识别在国内可能报 `network`，可换 Safari 或打字作答。
